## 规则核对与本次行为

重新读取了项目父目录里的《403-无人车多车交互赛竞赛规则 2026版(1).pdf》。规则原文要求：

- 第一组锥桶距起点 2～4 米，第二组距第一组 2～4 米；每组 5～7 个，与道路中线约 30° 摆放。
- 30° 是锥桶排列相对道路中线的夹角，不能直接写成舵机角度，也不能在未标定的透视图像上直接套 `tan(30°)`。
- 项目二要求在横道前停车线处不压线停车 5 秒，再继续通过终点。横道距离终点约 1 米。

用户本次明确要求“横道停车后不再重新起步”。因此添加 `code/Lu_UI.h` 中的 `MK_FINAL_STOP=1` 作为调试行为，保留原识别触发位置，触发后持续停车。没有宣称这个行为符合原规则的全程要求，也没有将停车位置改成已经实测的“整车过横道”位置。

需要恢复原来的 5 秒后继续行驶行为时，单独将该宏改为 0。该分支也已做桌面回归验证。

## 修改原理

1. **起步保护真正执行。** 原代码只把 `steer_settle` 写进诊断位，后面仍照常计算方向。本次由 5 ms 转向中断计满 200 次保持中位，CPU0 主循环不再用循环次数估算时长。
2. **单边补线不额外跨一条道。** 只看到一条边界时，无法确定它就是整条双车道的最外侧。原先加减 1.5 个车道宽可能把目标从本道推到画面边缘，现仅使用半个单道宽补偿。
3. **普通巡线和绕行分开限幅。** 普通巡线目标限制在中心 ±10 像素，并限制每周期变化；已确认的锥桶动作仍然能使用原绕行目标，不能把正常纠偏当作变道。
4. **无效图像回中。** 不再保持上一次大转向 2 秒。拟合样本不足时发布 `Point=0`，避免 NaN 转坐标后参与控制。没有同时改曝光、阈值、舵机标定或 PID 增益。
5. **锥桶按已处理帧确认。** CPU1 完成一轮图像算法后递增 `vision_processed_frames`；转向侧只在序号更新时累计确认，不能把同一张图在 5 ms 中断里重复读 3 次就当 3 帧。
6. **横道停车不再定时重启。** `MK_FINAL_STOP=1` 时维持停车状态并置终点停车锁存；电机输出层也将两轮 PWM 置零并清除 PID 历史，避免零目标下仍残留驱动。PWM 置零的实际滑行距离仍取决于电机驱动和车速，需实车测量。

当前锥桶绕行仍是固定左右顺序、里程退出加超时兜底，没有实现按 30° 锥桶走廊闭环跟踪。本次只抑制直线段偶发识别导致的过早动作，不把它当作完整锥桶方案。

## 新增日志字段

| 字段 | 含义 |
|---|---|
| SM | 转向模式：0 未放行、1 起步保护、2 普通巡线、3 锥桶动作、4 图像无效、5 最终停车 |
| RT / TP | 限制与保护前的候选目标 / 实际送给舵机控制的目标 |
| LK | 当前选道参数 |
| MS | 5 ms 控制定时计数换算的毫秒；T 仍是日志条目序号 |
| PC / FC | 已处理图像数量 / 摄像头采集完成数量 |
| VS | 左右轮目标，单位为每 5 ms 编码器计数，不是厘米每秒 |
| VE | 左右轮实际编码器计数，左右顺序与 VS 一致 |
| VP | 左右轮最终 PWM 命令 |
| ES / FS | 最终停车已锁存 / 横道最终停车调试宏 |

日志字段从不同控制与感知时刻读取，并非一份受同步保护的完整帧快照。判断因果时看连续序列，不只看一条。日志缓冲为静态 1024 字节，避免占用 CPU0 仅 2 KB 的用户栈。
