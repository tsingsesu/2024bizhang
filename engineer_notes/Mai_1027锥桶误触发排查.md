# Mai 锥桶误触发排查：V25

## 急诊卡

- **锥桶识别与自动避障保持开启**：`CONE_ACT_ENABLE=1`，V25 日志应显示 `CA=1`。关闭动作的临时改动已经撤回，没有提交或推送。
- `CN` 是原始白色候选数量，不是真实锥桶数量；现在不会仅凭 `CN>=2` 就确认锥桶组。
- `CG=1` 仅表示候选点通过了图像几何筛选；仍需原控制侧连续 3 个处理帧确认，才允许进入 `SM=3`。
- `GP=支持点数/横向跨度/纵向跨度/近似线残差`。几何筛选依据像素，不是米制标定。
- 保持 V24 的横道最终停车行为，`ES=1` 后两轮 PWM 持续为零。
- V25 将终点探测计数从重名的 `R` 改为 `SR`；行内的 `R` 只表示右边界。解析 V23/V24 时应保留第一个 R，避免被后面的终点计数覆盖。

## 原策略为什么会误转

原始识别主要根据横向白段宽度，将 5～40 像素的白段合并成 blob；允许仅占 1 行。两块这样的白斑就可以得到 `cone_ok=1`。

这意味着同一物体的两条白带、两块碎片、较粗的车道线或反光都可能凑够候选数。V24 的连续 3 帧确认只能去掉短暂噪声，持续出现在画面中的错误白斑仍可连续通过。

绕行动作的方向仍然是旧策略的“先左后右”，目标偏置、里程退出和超时兜底也预先设定。所以错误候选一旦确认，就会真正改变选道和舵机目标，随后即使原始候选消失，也会先执行完本次锁存动作。

## 本次只收紧锥桶组的确认依据

新增 `code/Mai_cone_geometry.h`，由 `Cone_Scan()` 实际调用：

1. 邻近的候选点做去重，避免一条白带的碎片重复计数。
2. 至少 3 个分离候选点，横向跨度至少 16 像素，纵向跨度至少 8 像素。
3. 用候选点对建立直线假设，检查是否有足够支持点落在允许误差内；允许额外不相关的噪点存在。
4. 横排、竖排、只有两块白斑等情况不再通过确认。原始 `CN` 和屏幕候选点仍保留，便于观察漏检与误检。
5. `cone_ok` 由几何检查结果产生，控制侧原来的连续处理帧确认继续生效。

这不是将舵机设成 30°，也没有声称像素斜率等于规则中的道路平面 30°。相机透视、安装高度和俯仰尚未标定，不能直接套角度。绕行路径本身没有在本轮改成实时规划。

这些是需要实车验收的候选筛选条件。只能看到 1～2 个候选、候选跨度不足或目标被遮挡时，触发会延后或不触发；需要同时验证真实锥桶是否还能及时绕过，不能只验收无障碍不转向。画面中形成类似斜向分布的其他特征仍可能误通过。
