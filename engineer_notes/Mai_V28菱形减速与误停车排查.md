# V28 菱形减速与误停车排查

## 急诊卡

- 拉取最新 master 后，在 ADS 中重新编译、烧录；日志应显示 V28。
- 正常流程：MK=0 正常行驶 → MK=1 逐渐降到半速并保持 → MK=2 横道前静止满5秒 → MK=3 低速通过 → MK=4 永久停车。
- 菱形和两菱形之间均不应进入 MK=2。若停车，检查 MK、DH、SM、VL、LR、LN、PC；不要只凭停车地点判断误识别类型。
- 无线日志继续使用现有接收脚本。测试完成后直接读取原日志文件。

## 日志证据

2026-10-27 的 V27 日志中，21:50:06 至21:50:14 多次出现 MK=1→0，目标速度没有持续维持低速。旧逻辑在菱形消失且 Distance 超过60时恢复原速；该变量还是旧里程单位，不能当作真实60厘米。

21:50:15 和21:50:30 的停车记录为 MK=0、DH=1、SM=4，VL 分别为3/48和3/44，说明触发的是持续缺少可用车道的保护。21:52:50 的停车也属于该类。它们不能直接证明横道误识别。

21:51:28 的记录为 LC=24、DI=1/17/8，标线判断使用了有效车道扫描范围以外的边界。Image_Handle 提前结束后，远处边界数组会保留旧值，原 Marker_Scan 没有排除这些行。

## 修改

1. 首次确认菱形后保持减速状态，直到横道停车，不再因菱形消失或短距离到期恢复全速。沿用原软减速和50%目标速度。
2. 菱形使用当前二值图中央窗口中的两条细边，要求连续多行且左右边向相反方向移动，排除简单平行竖线。判断不再依赖过期的远处车道边界。此窗口依然需要实车确认，偏离窗口或曝光不佳时可能漏检。
3. 横道的车道宽度判断只使用本帧已扫描的行；同时要求当前图像有至少两条由黑色间隔分开的中心白带，并保留绝对宽度及相对车道宽度条件。一个厚白块不能直接满足横道条件。
4. 标线确认按完成处理的不同相机帧计数：菱形8帧，横道15帧，近处横道位置另需3帧。避免中断重复读取单帧，以及远处横道历史直接确认一次近处误报。
5. 首选循线行被白标记或障碍打断时，向下寻找本帧更近的可用边界；备用位置须连续两行可用。允许使用扫描终止行52以内的近处边界。全无可用边界及相机断帧仍会停车，自动避障保持开启。

`python3 Mai_tests/Mai_control_regression.py` 和 `python3 Mai_tests/Mai_cone_detection_regression.py` 均通过。新增持续减速、当前图像菱形、平行线排除、单白块排除、多条横道、旧边界排除、冻结帧、近处车道恢复场景；保留横道5秒与最终停车、ToF、里程和锥桶绕行回归。
