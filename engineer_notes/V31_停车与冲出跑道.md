- 无线已改回自己的热点：SSID `11` / 密码 `123321123`，目标 IP `192.168.214.24:8086`。

- 判读停车原因仍然看 `IR`：`0x10` 是持续丢线，`0x08` 是相机断帧，`0x20` 是横道等待。

## 两个毛病的原因（都在 V24 引进的）

### 1. 时不时停车

`TRACK_LOSS_TICKS` 原来是 **40**，也就是连续 **200ms** 认不到车道就 `drive_inhibit`：

```c
/* control.c */
#define TRACK_LOSS_TICKS      (40)    /* 200 ms without a usable lane. */
```

`track_bad_ticks` 在 `S3010_Control` 里累加，判据是
`pt<0 || Line_Count 越界 || 第 22 行宽 <20 或 >140`。分道线断口时 `Left_Line` 会掉到 1、
`Line_Count` 也会跳出 0~52，属于正常现象，却每 200ms 就满足一次停车条件。

而且停车以后 `out_L/out_R` 被清零，`MOTOR_RAMP_TICKS=40` 意味着要 **5 秒**才重新爬回
目标速度 25，所以体感是「跑一段、停一下、又慢慢挪起来」。

### 2. 冲出跑道

```c
#define STEER_STRAIGHT_RANGE  (10)    /* Normal following: bounded correction, not a lane change. */
```

正常循线的目标点被硬夹在 `Point_Mid±10` = `50~70`。一条道在图像里约 76px，
车道中心一旦偏出 10px 舵机就没有更多余量，弯道里根本转不够。

同时坏帧分支是 `lane_target = Point_Mid; Point_PID.LastError = 0;` ——
**任意一帧**不可信就把目标点直接拽回 60（没有斜坡），车在弯里被反复回正。

## 改动（`code/control.c`）

| 项目 | 原值 | 新值 | 说明 |
|---|---|---|---|
| `STEER_STRAIGHT_RANGE` | 10 | **45** | 恢复 V23 的转向余量（单边补线分支本来就是 ±45/±25） |
| `STEER_TARGET_STEP` | 1 px/5ms | **2 px/5ms** | 60→105 约 110ms，仍保留斜坡避免突变 |
| `TRACK_LOSS_TICKS` | 40 (200ms) | **400 (2s)** | 和 V23 的「连续 2 秒才回中」一致 |

坏帧分支改成保持：

```c
if(bad)
{
    if(track_bad_ticks < 60000) track_bad_ticks ++;
    if(track_bad_ticks >= TRACK_LOSS_TICKS)
        lane_target = Point_Mid;   /* 真丢了才回中 */
    steer_mode = 4;
}
else
{
    track_bad_ticks = 0;
    pt = range_protect(pt, Point_Mid - STEER_STRAIGHT_RANGE, Point_Mid + STEER_STRAIGHT_RANGE);
    if(lane_target < pt) lane_target += STEER_TARGET_STEP;
    else if(lane_target > pt) lane_target -= STEER_TARGET_STEP;
    steer_mode = 2;
}
pt = lane_target;
```

V24~V30 的其它东西都保留：锥桶几何确认（`CG/GP`）、起点 100cm 内不动作（`CONE_ARM_CM`）、
第二组逐渐收舵（`CONE_RETURN_TAPER_FROM`）、横道判据不依赖车道边界（`CB`）、
MK 五状态机、五秒静止计时、`IR` 停车原因位。

- 只做了静态检查：括号 94/94、`#if`/`#endif` 8/8、注释外无非 ASCII。
  **没有在 TASKING 下编译过，也没有实车验证。**
- 如果还停，先看 `IR`：
  - `IR=0x10` 说明还在丢线，看 `VL=`（左边界/右边界）和 `DH=1`，是边界扫描塌掉，不是这条修的问题；

  再把 `STEER_STRAIGHT_RANGE` 放大到 60。
