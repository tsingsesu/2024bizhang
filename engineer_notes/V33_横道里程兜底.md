# V33 横道停车：视觉判据失效，改里程兜底

## 日志证据（log_20261028_162830.txt，V32）

| 位置 | 现象 |
|---|---|
| 全程 | `CW` 第一位 = `mk_cw_seen` **一直是 0** |
| T=174~184 (DC 1167~1220cm) | `CB=1`、`CW=0/0/16~34`、`NW=1`、`L=1 R=99 W=98` |
| 全程 | `CB`（`mk_cw_bands`）**最大只有 1** |
| 全程 | `MK` 0 → 1（T=87，DC=669cm 确认菱形）→ 再没动过 |
| 结尾 | `DC=1280cm` 撞终点墙，编码器归零，`To≈400mm` |

`mk_cw_seen = (cw_rows >= 4 && bands >= 2)`，而 `bands` 每帧都是 1，条件永远不成立。

原因是几何形状：斑马线在近处是一整片白，`Mai_Crosswalk_Scan` 靠「两条带之间
有 ≥2 行黑缝」来分辨，实车上黑缝被二值化填掉，`height` 一路涨到 34 行，`bands` 停在 1。
所以不是 `MK_STOP_ROW` 的问题（V32 已经把 45 降到 40），是**根本进不了 `mk_cw_seen`**。

## 改动（`code/control.c`）

```c
#define MK_CROSS_CM   (1100)   /* 走到这个里程(cm)就按横道处理，0 = 关闭 */
```

```c
if(mk_state == 0 || mk_state == 1)
{
    if(...视觉判据...)                                  { mk_state = 2; }
    else if(MK_CROSS_CM > 0 && run_distance_cm >= MK_CROSS_CM)  { mk_state = 2; }  /* 新增 */
    else if(mk_state == 0 && mk_dia_run >= MK_DIA_CONFIRM)      { mk_state = 1; }
}
```

后面的流程不变：`mk_state=2` 断电机、编码器静止 5 秒 → `mk_state=3` 以
`MK_CROSS_SPEED=10` 低速通过 → 压过白条后 50cm（`MK_CLEAR_CM`）→ `mk_state=4` 永久停车。

## 1100 这个值怎么来的

- 这一跑总里程 `DC=1280cm`（撞终点墙）。
- 近处白条（`NW=1`）从 **DC=1156cm** 开始，一路到 1220cm。
- 从 25 的目标速度断电机，滑行大约 10~20cm，所以 1100 大致停在 1115 左右，
  正好压在斑马线前面。

**如果停得太早/太晚，只改 `MK_CROSS_CM` 一个数**（10cm 一档调）。
想关掉这个兜底就设 0。

## 顺带确认（这一跑是好的）

- 两次绕障**都触发了**：`LK` 75 → 0（第一次往左，T=42）→ 100（第二次回右，T=63），
  收尾 `CT=2/0`（`cone_group_cnt=2`）。
- 终点前不再左打：`NW=1` 从 T=172 持续到 T=184，目标点被压在中线。
- 循迹：`SM=2` 占绝大多数，`GB=0x0000` 为主，没有 10-26 那种一路 `SM=4` 的情况。

## 还没解决

- 视觉横道判据本身仍然是坏的（`bands>=2` 在实车上永远不成立）。
  要么按「同一行里有多条竖直白条」重写 `Mai_Crosswalk_Scan`，
  要么就接受里程兜底，`NW` 只用来做转向回正。

# V34 停车点前移 + 绕障距离上限

## 第二跑（log_20261028_163630.txt）说明的事

- **横道停车成功**：`T=159 DC=1101` → `MK=2`、`IR=0x20`、`WT` 0→1560ms（5 秒在计时）。
- **但停住时 `NW=1`**（第 45~58 行里有白条），也就是车头已经压在斑马线上 → 停车点偏晚。
- **绕障在 10 米处误触发**：`T=127 DC=934` `CN=6/36/106 CG=1 GP=4/87/22/1`，
  `T=139 DC=1001` `CN=9/36/20` → 触发第二组绕障，`LK` 75→100（往右）。
  紧接着 `T=141` `CN=7/55/58`（`cone_near=55`，车头前 30cm 一片白）—— 那是斑马线白条。
  结果是车在横道前 1 米往右甩一下，再停。**这就是「横道前面右转」的真正来源**，
  不是转向公式的问题，是绕障被白线骗了。

`Mai_Cone_Group_Valid` 只要求「3 个点、横跨 ≥16px、竖跨 ≥8px、近似共线」，
一条横着的白线（87px 宽、22px 高、残差 1）完美满足。这是几何判据的固有弱点，
靠调参救不回来。

## 改动

| 宏 | 原 | 新 | 说明 |
|---|---|---|---|
| `MK_CROSS_CM` | 1100 | **1050** | 停住时压线，整体前移 50cm |
| `CONE_MAX_CM` | （无） | **600** | 绕障只在前 6 米触发；实测真锥桶在 1.9~4.2 米 |

```c
if(... && cone_near >= CONE_TRIG_ROW &&
   cone_group_cnt < CONE_MAX_GROUPS &&
   (CONE_MAX_CM == 0 || run_distance_cm <= (double)CONE_MAX_CM))
```

`CONE_MAX_CM = 0` 就恢复成原来的「不限距离」。

## 标定方法

- 停车位置：看停住那一行的 `DC`。压线 → `MK_CROSS_CM` 减 10；离得太远 → 加 10。
- 摄像头角度改了以后：`cone_near`、`NW`、`GP` 的行号都会变，**但 `DC`（里程）不变**，
  所以 `MK_CROSS_CM` 不用重标。绕障的 `CONE_TRIG_ROW` / `CONE_MAX_CM` 可能要重新看一遍。

# V35 停车点微调 + 第二次绕障转角

跑 V34 后现场反馈两条：

## 1. 停早了 1~2 秒 → `MK_CROSS_CM` 1050 → 1075

这一版车速约 **25cm/s**（`DC` 从 0 到 1103 用了约 41 秒），所以
**1 秒 ≈ 25cm**，1~2 秒 = 25~50cm。

- `1100` 压线（V33 实测）
- `1050` 早 1~2 秒
- 取中间 `1075`

还早 10cm 就加 10，压线就减 10。

## 2. 第二次避障转角不够 → `CONE_RETURN_TAPER_FROM` 80 → 120

V30 加的「第二次绕障逐渐收舵」在 `used > 80`（CONE_LANE_CM=170 的一半不到）就开始把
`half` 从 18px 线性减到 0，动作后半段几乎没有横向需求，车回不到右道。

现在前 **120** 个 O 单位都保持满 18px，只在最后 50 个单位（约 15cm）收干净：
既找回转角，又保留解除锁存时的平滑过渡。

再不够的话，下一个旋钮是 `CONE_LANE_HALF`（18 → 20），不要再改收舵起点。

# V36 停车点取中 + 第二个菱形后恢复原速

## 1. `MK_CROSS_CM` 1075 → 1063

| 版本 | 参数 | 现场反馈 |
|---|---|---|
| V34 | 1050 | 早 1~2 秒（25cm/s，约 25~50cm） |
| V35 | 1075 | 又压线了 |
| V36 | **1063** | 取中间 |

停车位置本身有 ±20cm 的波动：V35 那跑在 `DC=1064~1067` 因为丢线停了 2 秒
（`IR=0x10`），再慢慢挪到 1075 才进 `MK=2`。手摆车的位置每次也不完全一样。
所以别再 10cm 一档纠结，先看 1063 落在哪边。

## 2. 减速幅度 `MK_DIA_SPEED_PCT` 50 → 70

规则只要求「看到减速标线后减速」，没必要砍一半。`25 × 70% = 17`（原来是 12）。

## 3. 过第二个菱形恢复原速

原来 `mk_state = 1`（减速 50%）从第一个菱形一直保持到横道，第二个菱形之后还在爬。
现在加了菱形计数：

```c
static uint8 mk_dia_cnt = 0, mk_dia_latch = 0;

if(!mk_dia_seen) mk_dia_latch = 0;
else if(mk_dia_run >= MK_DIA_CONFIRM && !mk_dia_latch)
{ mk_dia_latch = 1; mk_dia_cnt ++; }        /* 一个菱形只计一次 */
```

状态机里：

```c
else if(mk_state == 1 && mk_dia_cnt >= 2)  { mk_state = 0; }   /* 第二个过了 -> 恢复原速 */
else if(mk_state == 0 && mk_dia_cnt == 1 && mk_dia_run >= MK_DIA_CONFIRM) { mk_state = 1; }
```

**验证方法**：日志 `MK` 应该出现 `0 → 1（第一个菱形后）→ 0（第二个菱形后）` 的回头，
而且 `VS` 从 12 回到 25。如果 `MK` 一直是 1，说明第二个菱形没被确认，
要看 `DI=` 那三个数。

# V37 DL1B（ToF）直接发车：30~40cm

## 原来的发车判据为什么用不了

`user/isr.c` 里的非接触发车是「投票制」：

1. 先看够 1 秒「前方 4m 内没东西」（一个有效样本都没有）才布防 `tf_armed`
2. 布防后最近 12 个样本里 8 个 <50cm → 发车

问题在布防：**ToF 朝前稍微向下时，地面一直在量程里，样本不断**，
`tf_last_tick` 每秒都在刷新，`tf_armed` 永远为 0 → 怎么挥手都不发车。

## 新增：窗口直通

```c
#define TF_BAND_LO_MM (300)   /* 下限 30cm */
#define TF_BAND_HI_MM (400)   /* 上限 40cm */
#define TF_BAND_N     (3)     /* 连续 3 个样本落在窗口内就发车 */
```

```c
if(d >= TF_BAND_LO_MM && d <= TF_BAND_HI_MM)
{
    if(tf_band < 255) tf_band ++;
    if(tf_band >= TF_BAND_N) start_trigger = 1;
}
else tf_band = 0;
```

**不要求布防**（这正是原判据的死结），只要连续 3 个 DL1B 样本落在 300~400mm 就走。
原来的 12 选 8 投票保留，两条路任意一条成立都算数。

## 调试模式也生效

`START_MODE = 2`（上电 20 秒自动发车）现在改成「20 秒 **或** DL1B 触发」：

```c
((2 == START_MODE) && ((isr_tick_5ms >= (START_DEBUG_DELAY_MS / 5)) || start_trigger))
```

`START_MODE = 1` 仍然是比赛用的「只有 ToF 能发车」。

## 注意

- 这个窗口**没有防抢跑保护**：上电时如果正好有东西停在车前 30~40cm，车会直接走。
  要更严格就把 `TF_BAND_N` 加到 5~8，或者在条件里加上 `tf_armed`。
- 手伸到 20cm 以内不会命中这个窗口，但会走原来的 `<50cm` 投票那条路（前提是布防成功）。
- 日志里 `SB=ready/base/hold`：`base` 就是 DL1B 当前读数（mm），`hold` 是投票命中数。

/* 旧 */
if(((1 == START_MODE) && start_trigger) ||

# V39 横道改回视觉识别（按并行条纹数）

## 旧判据为什么永远来不及

`Mai_Crosswalk_Scan` 原来找的是「一行里一条**很宽**的白带」（≥30px 且横跨画面中心）。
但斑马线的条纹是**沿行车方向**排的，远处画面里是一排**并排的窄条**，
没有哪一条能横跨 30px；只有车头压上去、相邻条纹糊成一片时才出现宽白带。

V37 的日志正好证明了这一点：

```
行进中：   CW=0/0/3、0/0/6      ← 只有 2~6 行
停住压线后：CW=0/0/51           ← 停下来才涨到 51 行
```

所以 `cw_rows >= 4 && bands >= 2` 这个条件，在「车还没压上去」的时候永远不成立。

## 新判据：一行里有几排并排窄白条

```c
#define MK_STRIPE_MIN   (2)    /* 白条最窄 2px */
#define MK_STRIPE_MAX   (14)   /* 最宽 14px，再宽就是白块/停车线 */
#define MK_STRIPE_GAP   (2)    /* 白条前面至少隔 2px 黑 */
#define MK_STRIPE_N     (3)    /* 一行里至少 3 条 */
#define MK_CW_FILL_PCT  (30)   /* 整行白色占比至少 30% */
#define MK_CW_COL_L     (20)   /* 扫描窗口比菱形宽（原来 36~84，只有 49px） */
#define MK_CW_COL_R     (100)
```

一行同时满足「≥3 条窄白条」和「白色占窗口 ≥30%」才算斑马线的一行。

那个 30% 是关键：左边线 + 中线 + 右边线也是 3 条，但它们加起来只有 ~6px，
占 80px 窗口的 7%，过不了；斑马线是 40%~50%。

排除掉的：减速菱形（2 条细线）、锥桶（一个白块）、停车线（一条 >20px 的宽横线）。

`mk_cw_seen` 不再要求 `bands >= 2`（斑马线在画面里是连续一大片，bands 只会是 1）。

## 里程降级为兜底

| 参数 | 原 | 新 |
|---|---|---|
| `MK_CROSS_CM` | 1055（主判据） | **1120（只在视觉完全失败时兜底）** |
| `MK_CW_MIN_CM` | 无 | **800（前段不认横道）** |

终点墙实测在 `DC≈1174`，兜底放 1120 是为了「绝不被骗停，也绝不冲过终点」。

## 验证

日志里 `CW` 应该从 `0/0/x` 变成 `1/行号/行数`，**在车头压上斑马线之前**就出现；
`MK` 变成 2 时记录一下 `DC`。

- 如果 `CW` 一直是 `0/0/0`：条纹判据没命中，先看 `CB`（现在的含义是"连续行段数"，应该是 1）
- 如果 `CW=1/xx/4` 但 `MK` 不跳 2：说明 `mk_cw_near` 到不了 `MK_STOP_ROW=40`，把它降到 36
- 如果停在斑马线后面：把 `MK_STOP_ROW` 加到 44

## 本轮没动的

「第二次转弯容易跑出跑道」没有改。需要知道是往**里**（压中线）还是往**外**（出边线）跑的，
以及大概在第几米——日志里的 `TP` 只能看目标点，看不出车身实际位置。

# V40 绕障结束后的「回正窗口」

## 现象（17:04 那跑的日志）

第二次绕障 `T=106` 开始时 `TP=78`、`d=869`（往右）。绕完以后：

```
T=113  DC=487  d=863  TP=78  NT=82     ← 还在往右
T=114  DC=500  d=946  TP=50  NT=53
T=115  DC=508  d=987  TP=40  NT=40     ← 满舵左打（987 = Pwm_Max）
T=116  DC=518  d=981  TP=46  NT=47
T=117  DC=528  d=987  TP=38  NT=38     ← 连续满舵左
T=118  DC=539  d=987  TP=44  NT=45
```

车身还在往右斜的时候，舵机突然满舵左打 → 车被甩出赛道。

## 原因

绕行结束后 `Left_Line` 正好掉到 1（左边线扫丢），只剩右边线，
单边补线 `pt = Right - lane_w/2` 在 `R=78` 时算出中心 `pt=40`（偏左 20px）。

而 `PlacePID_Control` 是增益自适应的：

```c
sprt->KP = (20.0*iError)/100;     // 20px 误差 -> KP=4 -> 输出 80
```

舵机总行程只有 ±70，所以 **±20px 的目标误差就是满舵**。
侧向一旦被坏边界拉偏 20px，必然顶死。

## 改动

```c
#define CONE_SETTLE_TICKS   (160)   /* 绕行结束后回正 800ms */
#define CONE_SETTLE_HALF    (6)     /* 期间目标点最多偏中线 ±6px */
```

```c
if(latched) { ... }
else if(cone_settle)          /* 变道刚结束的 800ms */
{
    if(cone_settle) cone_settle --;
    if(pt < Point_Mid - 6) pt = Point_Mid - 6;
    if(pt > Point_Mid + 6) pt = Point_Mid + 6;
    cone_steering = 1;        /* 不让循迹在这一段改它 */
}
```

±6px 对应约 ±21 个占空比，车会先走直；800ms 后正常循迹接管。
两组绕障都会走这个窗口（`cone_settle` 在松锁存时置位）。

## 验证

看绕障结束后的 `CT` 从 100 掉到 0 之后那一段：

- `d` 应该稳定在 `933` 附近（中位 917 + 微调 16），不再出现 `987` / `850` 这种贴限幅的值
- `TP` 应该稳定在 54~66

如果还是有一下甩，把 `CONE_SETTLE_TICKS` 加到 240（1.2 秒），
或者把 `CONE_SETTLE_HALF` 降到 4。

# V41 第二次绕障甩出赛道：回正窗口改成条件式

## 先说 V40 的一个事故

V40 的两个 `#define`（`CONE_SETTLE_TICKS` / `CONE_SETTLE_HALF`）被插到了
`CONE_LANE_HALF` 那条**多行注释的中间**：

```c
#define CONE_LANE_HALF      (18)   /* ... 14->18 取中间。
#define CONE_SETTLE_TICKS   (160)  /* ← 在注释里，等于没定义
#define CONE_SETTLE_HALF    (6)    /* ← 在这里面
                                      目标点 42、duty 约 980。      ← 变成代码了，E207
                                      22=满舵987(...) / 14=972(...) */   ← E207
```

**V40 编译不过。** 已经修好，宏现在在注释块之后。教训：插宏不能锚定在一个
「行尾开注释、下一行还在注释里」的 `#define` 上。

## V38 日志把机制坐实了

```
T=77~80  CT=2/100  d=869      ← 第二次绕障，满舵右
T=82     CT=2/0    d=933      ← 结束
T=83     L=53 R=92  W=39      ← 假配对，宽度只有真车道一半
T=84     L=1  R=100 W=99      ← 左边线出画，单边补线算出中心 62（还在往右要）
T=87     L=1  R=70  W=69
T=88     L=1  R=48  W=47      ← 右边线退到画面中线左边 = 车已经压到右边界外
                              → TP=30 → d=987 满舵左
```

车在变道后**继续向右冲**，冲过右边界，然后被满舵向左掰。

## 改动

1. **宽度合理性**（`control.c` 两边界分支）：

```c
if(l_ok && r_ok && w > 20 && !(lane_w_ema > 20 && w * 3 < lane_w_ema * 2))
```

宽度不到已知道宽（约 76px）的 2/3 就不算数；并且只有「和已有估计差不太远」的
宽度才准进 `lane_w_ema`，避免被假配对越学越小（日志里 W=39 就是被学进去的）。

2. **回正窗口改成条件式**（原来是固定 800ms）：

```c
else if(cone_settle)
{
    int32 ww = steer_lane_right - steer_lane_left;
    uint8 sane = steer_lane_left > 6 && steer_lane_right < 117 &&
                 ww >= 46 && ww <= 108;
    if(sane) cone_settle = 0;          /* 扫描恢复正常 -> 立刻交回循迹 */
    else if(cone_settle) cone_settle --;   /* 最长 2.5 秒 */
    pt 夹在 60 ± 6;
    cone_steering = 1;
}
```

只要边界还是烂的（L=1 / R=48 这种），就一直按中线走，不给它满舵的机会。

## 如果还冲出去

那就是**变道本身转多了**，不是回正的问题。下一个旋钮：

```c
#define CONE_RETURN_TAPER_FROM (120)   /* 120 -> 90：更早开始收舵 */
```

或者把 `CONE_LANE_HALF`（18）单独给第二组调小。

# V42 撤掉回正窗口（它是帮倒忙的）

## V41 实测：第一次绕障也冲出赛道了

```
T=69~74  CT=1/100  d=987  ← 第一次绕障，满舵左
T=75     CT=1/0    d=940  TP=54   L=1 R=86
T=76     d=940  TP=54  NT=-1   ← 循迹想纠偏，被 cone_steering 挡住
T=78     d=940  TP=54
T=79     d=926  TP=66  L=49 R=117  ← 车已经贴到左边界
```

**车身是斜的**。目标点定在中线，车就沿斜线继续漂；`cone_steering = 1`
还把循迹的纠偏关掉了。回正窗口越长，漂得越远 —— 所以 V41 比 V38 更糟。

## 改动

1. **删掉整个回正窗口**（`cone_settle` / `CONE_SETTLE_TICKS` / `CONE_SETTLE_HALF` /
   `STEER_LANE_W_MIN` / `STEER_LANE_W_MAX` 全部移除），绕行结束立刻交回循迹。

2. `CONE_RETURN_TAPER_FROM` 120 → **90**：第二次绕障实测冲过右边界
   （V38：绕完 `R` 从 110 一路退到 48，等于车头已经出了右边线），
   提前 30 个 O 单位开始收舵，少转一点。

3. 保留 V41 的宽度合理性检查（两边界宽度不到已知道宽 2/3 就不信这一帧）。

## 教训

「先别打方向让它走直」这个思路是错的：舵机回中只是**不再增加**转角，
不会消掉已有的车身偏角。已经斜了就得更早、更轻地反打，而不是锁在中线。

## 如果还冲出去

第二组还是转多的话，下一个旋钮是 `CONE_LANE_HALF`（18 → 15），
它同时缩小两组，先试 16。

# V43 过横道走直 + 停车后起步加快

## 1. 终线前方向乱（V42 日志）

`MK=3` 那一段（`DC=1021~1172`）车道宽度只剩 29~37（真车道 76）：

```
T=147  L=22 R=59 W=37  TP=58
T=168  L=17 R=46 W=29  TP=32  d=987   ← 满舵左
T=172  L=48 R=63 W=15  TP=82  d=863   ← 又满舵右
```

斑马线白漆把左右边线全扫塌了，这时候循迹就是瞎打。

**改法**：`mk_state == 3` 直接进「走直」分支（和停车状态 2 一样），
目标点固定 `Point_Mid`，`SM=7` 标出来。车停 5 秒时本来就是正的，
这 1.5 米直接过去。

## 2. 重新起步太慢

```
T=139 VS=0 → T=143 VS=5 → T=145 VS=7 → T=147 VS=10
```

两个原因：
- `MK_CROSS_SPEED = 10`（正常 25）→ 改成 **18**
- 软启动 `MOTOR_RAMP_TICKS=40`（1 个/200ms）→ 0→18 要 3.6 秒。
  过横道这段按 `MOTOR_RAMP_TICKS/5` 走，0→18 约 0.7 秒。

注意软启动只加快了 `mk_state==3` 这一段，全局起步（0→25，5 秒）没动。

- `VS` 从 0 到 18 大约 0.7 秒（日志上约 3 个 T）

# V44 过横道的方向补偿

V43 的「过横道走直」生效了（`MK=3` 时 `SM=7`、`d` 恒 933、`TP` 恒 60，不再满舵乱打），
但现场反馈**终点前稍微右偏**，日志也证实：

```
T=159  L=60 R=71 W=11
T=166  L=52 R=92
T=171  L=16 R=65     ← 左右边线一起往左退 = 车在往右偏
```

L 和 R **同时**向左退，说明是车身在偏，不是扫描乱了。1.2 米偏了约 12~15cm，
换算约 7°。

原因：过横道时方向被固定在 `Steer_Mid + Steer_Trim = 917 + 16 = 933`，
这个「中位」本身差 15 个占空比左右。

## 改动

```c
#define MK_CROSS_TRIM   (16)   /* 正 = 往左（duty 变大），负 = 往右 */
```

```c
SD5_Duty = range_protect(Steer_Mid + Steer_Trim +
                       ((MK_ACT_ENABLE && mk_state == 3) ? MK_CROSS_TRIM : 0),
                       Pwm_Min, Pwm_Max);
```

**只影响 `MK=3`（过横道）这一段**，正常循迹、绕障、停车都不受影响。

## 怎么调

看 `MK=3` 那一段的 `L` / `R`：

- 两者都往左退（车右偏）→ `MK_CROSS_TRIM` 加（比如 16 → 24）
- 两者都往右退（车左偏）→ 减（16 → 8），减到负数就是往右补

一次调 8 个占空比，大概相当于 3~4°。
