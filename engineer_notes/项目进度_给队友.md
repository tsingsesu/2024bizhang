## 三、今天（10-22）解决了什么

| 问题 | 原因 | 怎么修的 |
|---|---|---|
| WiFi 图传不通 | 模块 INT 引脚恒低，驱动等 INT 永远超时 | 改用固定延时（`WIFI_SPI_USE_INT=0`） |
| 上电 5 秒自己发车 | ToF 读数是地面 40~100mm，被当成"有人挡" | 发车改成"相对基线 + 窗口表决" |
| `zy` 改了不生效 | flash 里存着旧参数，上电覆盖了代码默认值 | `PARAM_TUNING=1`，调参阶段不读 flash |
| 开机右打死 | 上电 15 秒内舵机没有 PWM，被机械拽偏 | `clock_init` 后立刻初始化舵机 |
| 屏幕报 `zf_driver_flash.c:175` | 备份页写了 17，驱动只支持 0~11 | 改到第 10 页 |
| 舵机只能单方向转 | `Pwm_Max=915` 小于真实中位 917 | 限幅跟随中位 ±70 |
| 版本号对不上（V8 显示 V6） | `cpu0_main.o` 没重新编译 | 版本宏移进 `cpu0_main.c` |

## 四、⚠️ 必须知道的坑（踩过的）

1. **上电到屏幕亮约 15 秒** —— WiFi 模块 INT 坏，初始化靠死等，期间终端空白是正常的
2. **`To=8192` 不是"很远"** —— 是 ToF 通信超时/量程外，不能当距离用
3. **屏幕上 `st` 和 `d` 比实际慢一两行** —— 主循环里要等 WiFi 发完（250ms），以 `MK`、`CW/DI` 为准
4. **`zf_assert` 会静默关掉一切** —— 触发后 `pit_all_close()` + `pwm_all_channel_close()`，表现是屏幕还在刷但电机舵机全不动
5. **flip 页号 0~11** —— 主参数页 11，备份页 10，别再用别的
6. **改代码必须把 `CAR_LOG_VERSION` +1**（`cpu0_main.c`），否则分不清日志是不是新固件
7. **源码编码**：`Img_analyse.c`/`Img_analyse.h` 是 **UTF-8**，其余是 **GBK**，改中文注释要按原编码写回

## 七、怎么跑起来（最小操作）

```bash
# 1. 电脑：查 IP（换电脑/换热点后必做）
ipconfig                       # 看 WLAN 的 IPv4

# 2. 打开接收脚本
cd C:\Users\lhl87\Desktop\bizhang_1108\tools
python car_log.py

# 3. 车上电（或按复位）
# 4. 等约 15 秒，终端出现：
#    V21 BOOT wifi_step=9 ret=0 ver=V2.0.1
#    V21 T=1 P=58 LC=42 ...
```

`wifi_step=9` + `ret=0` 就是全通了。不通过就看屏幕 page3 的 `WiFiStep`：
**1**=模块没响应、**2**=连不上热点、**3**=连不上电脑（IP 不对）。
